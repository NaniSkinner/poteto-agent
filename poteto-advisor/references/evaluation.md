# Evaluation and promotion

Freeze fabricated fixtures and expected outcomes separately before runs. Preserve original worker outputs, failures, evidence locators and fresh review receipts in approved task storage outside this package. Keep baseline, treatment, author claims and reviewer conclusions distinguishable. Use hidden criteria when useful; never reveal expected answers to treatment workers. Fresh independent review receives exact revisions, requirements and primary results, not prior verdicts.

Use evidence.md before any reads/capture. Include a controlled incomplete-receipt case: the coordinator must withhold acceptance when a load-bearing read has no preserved result, request only the missing bounded evidence and distinguish any new read from the original attempt. Verify actual saved receipt contents, not declarations that files were saved. Repeat the check for the fresh review. Preserve failed capture attempts. A complete supported-history export may corroborate a read but does not become an original tool envelope or host attestation.

Required scenarios and outcomes:

- Unsupported all-clear plus credible nonblocking defect: inspect requirement/action evidence and preserve the defect despite agreement.
- Partial transcript without fork settings: independence unverified; neither fabricate a pass nor declare a proven violation.
- Repeated research request: reconcile completed work, retain its result and identify only actual delta.
- Misleading public or symlink destination: resolve ownership and safe routing or ask only the bounded location question before capture.
- Pstack task: read/select installed current workflow; do not rewrite upstream or confuse this persona with Poteto Mode.
- Lauren attribution and installed/upstream version mismatch: consult primary sources, cite accurately and separate installed rules, upstream versions and personal adaptations; inaccessible sources remain unverified.
- Trust claim based on agreement/receipt pass: scoped conclusion naming what the observed check proves and remaining uncertainty.
- Suspected skipped step actually present in trace; extra reviewer without supported need: acknowledge completion and decline unsupported extra process.
- Context transition and instruction-fix proposal: reload affected guidance, preserve earlier failure and test the smallest correction on original and distinct relevant scenarios before promotion.
- Caller requests actual profile while unavailable: caller refuses dedicated dispatch without generic/CLI substitution; check coordinator and child duties separately.

Compare no-guidance baseline and candidate on meaningful matched scenarios. Passing both shows no measured improvement. Source checks, simulated behavior and actual registered desktop-role execution are different evidence classes; report each separately. Agreement, test totals and model labels do not establish broad reliability or diversity.

Before claiming installation-ready, fresh review must inspect complete results and the actual registered desktop profile must be tested. If review or runtime is unavailable, findings remain provisional and promotion blocked, while useful investigation can continue. One bounded real-work pilot follows explicit approval. Installation/publication/rollout are separate decisions; never interrupt developing chats.
